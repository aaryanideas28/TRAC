# Nexora ML Stage: Random Forest Regressor & Baseline Benchmarking

## 1. Executive Summary

This document details the Machine Learning (ML) stage of **Nexora**, an AI-powered train traffic management system prototype. The objective of this stage is to train and rigorously evaluate a baseline **Random Forest Regressor** to predict the immediate future change in train delay ($\Delta delay_{t \to t+1} = delay(t+1) - delay(t)$) using genuine sequential observations collected via the RailRadar API pipeline.

- **Target Variable**: `target_delay_change` (Continuous regression target in minutes)
- **Model Algorithm**: `sklearn.ensemble.RandomForestRegressor`
- **Total ML Observations**: 77 genuine sequential observations across 5 Central Line trains
- **Data Splitting**: Chronological per-train split (70% train / 30% test) $\to$ 53 training rows, 24 testing rows
- **Zero API Invocations**: 0 RailRadar API calls made (100% offline reproducible pipeline)
- **Baseline Comparison Verdict**: **NO** — The naive zero-change baseline outperformed the Random Forest regressor on the 24-sample test set due to the short 23-minute observation window where 75% of delays remained constant.

   - `station_transition`: Binary indicator ($1.0/0.0$) signaling station change

- `run_id`, `collection_timestamp`, `train_name`, `journey_date`: Non-generalizable metadata identifiers.
- `future_delay`: Component of $t+1$ target; excluded to eliminate data leakage.
- `target_delay_change`: Prediction target variable $y$.
- `scheduled_arrival`, `scheduled_departure`, `actual_arrival`, `actual_departure`: Raw ISO timestamp strings whose temporal components are already captured via `time_of_day_minutes` and `delay_minutes`.
- `platform`: Excluded due to 54.55% missing values in raw API responses.

## 3. Data Leakage Prevention Protocol

To guarantee mathematical and temporal integrity:
1. **Strict Temporal Separation**: Feature matrix $X_t$ contains zero information from observation $t+1$.
2. **Chronological Splitting**: The dataset is split per train strictly in chronological sequence. Future observations are never present in the training set when testing on later observations.
3. **Isolated Preprocessing Pipeline**: The `ColumnTransformer` (including median imputation and one-hot encoding) is fitted **exclusively on the training split** ($X_{train}$). Test data ($X_{test}$) is strictly transformed using the fitted parameters.
4. **Unknown Category Handling**: `OneHotEncoder(handle_unknown='ignore')` safely maps unseen test categories to all-zero dummy vectors without crashing or leaking global category distributions.

## 5. Model Configuration & Baseline Benchmark

### 5.1 Model Specifications
- **Regressor**: `sklearn.ensemble.RandomForestRegressor`
- **Hyperparameters**:
  - `n_estimators`: 100
  - `max_depth`: 5
  - `min_samples_split`: 2
  - `min_samples_leaf`: 1
  - `random_state`: 42

### 5.2 Baseline Benchmark Definition
- **Zero-Change Persistence Baseline**:
  $$\hat{y}_{baseline} = 0.0$$
  This represents the real-world operational assumption that unless strong congestion or acceleration signals appear, a train's delay will persist unchanged into the next 1–2 minute interval.

### 5.3 Evaluation Metrics Definition
1. **Mean Absolute Error (MAE)**:
   $$\text{MAE} = \frac{1}{n} \sum_{i=1}^n |y_i - \hat{y}_i|$$
   Measures average prediction error magnitude in minutes directly interpretable by railway controllers.
2. **Root Mean Squared Error (RMSE)**:
   $$\text{RMSE} = \sqrt{\frac{1}{n} \sum_{i=1}^n (y_i - \hat{y}_i)^2}$$
   Penalizes large outlier delay prediction errors more heavily than MAE.
3. **Coefficient of Determination ($R^2$)**:
   $$R^2 = 1 - \frac{\sum (y_i - \hat{y}_i)^2}{\sum (y_i - \bar{y})^2}$$
   Measures the proportion of target variance explained by the model relative to the test mean.

## 6. Performance Evaluation & Comparison

### 6.1 Benchmark Results

| Model / Split | MAE (min) | RMSE (min) | $R^2$ |
| :--- | :--- | :--- | :--- |
| **Zero-Change Baseline (Test Split)** | **0.6667** | **1.2247** | **-0.1309** |
| **Random Forest Regressor (Test Split)** | **0.9297** | **1.3743** | **-0.4240** |
| Random Forest Regressor (Train Split) | 0.5892 | 0.9053 | 0.7857 |

### 6.2 Comparison Verdict
**Did Random Forest outperform the baseline?**

> ### **Verdict: NO**
>
> **Explanation**:
> On the 24-sample test set, 18 out of 24 observations (75.0%) had an actual delay change of exactly 0.0 minutes. Because the baseline constantly predicts 0.0, it incurs zero error on three-quarters of the test set and achieves an MAE of **0.6667 minutes**.
>
> In contrast, the Random Forest regressor (trained on 53 samples) attempts to predict fractional continuous adjustments (e.g., $+0.34$, $-0.24$, $+1.84$), which creates non-zero residuals on the zero-change test samples, resulting in an MAE of **0.9297 minutes** and RMSE of **1.3743 minutes**.

## 8. Dataset Limitations & Prototype Context

This model was trained as part of a **college prototype demonstration** under strict SIH hackathon constraints.

1. **Small Sample Size ($N=77$)**:
   - The dataset spans 77 observations over a single 23-minute acquisition window on 2026-08-21.
   - 24 test observations cannot provide high statistical significance or low variance error bounds.
2. **Temporal Window Homogeneity**:
   - Observations were collected during late evening off-peak hours (16:27 UTC / 21:57 IST). The dataset lacks morning peak rush-hour congestion, midday patterns, and weekend schedule changes.
3. **Recommendations for Next Project Phases**:
   - **For Model Refinement**: Expand acquisition over 2–4 hours across 15+ trains to collect ~500–1,000 sequential pairs.
   - **For Next SIH Stage (OR-Tools)**: The optimization stage can consume either the ML-predicted delay trends or baseline persistent delay states depending on dispatching confidence thresholds.
